# RTK天线模块 测试记录

**测试人员**：吴君涵
**测试日期**：2026年7月6日  
**测试环境**：NUC + RTK模块 / Ubuntu 22.04 / ROS2 Humble  
**所属组别**：算法组  


## 测试内容

本次测试包含三个部分：RTK定位代码逻辑验证、状态机节点调试、串口双向通信联调。


## 一、RTK定位代码逻辑验证（A3）

编写RTK定位节点，通过串口读取RTK模块的NMEA数据，解析GGA帧获取经纬度坐标，并转换为本地ENU坐标系，最后发布到ROS2话题供状态机调用。

使用pynmea2库对NMEA协议数据进行解析测试，模拟GGA帧输入后成功解析出纬度、经度、定位质量、卫星数量等信息。代码逻辑验证通过。

因RTK天线尚未放置到室外开阔环境，暂未接收到有效的卫星定位信号，待室外实测验证实际定位精度。


## 二、状态机节点调试（A4）

将状态机封装为ROS2节点，在NUC上调试各状态流转：

IDLE → PICKUP → TRANSIT ↔ AVOID → HANDOVER → RETURN → IDLE（ERROR可随时切入）

7个状态均可正常切换，状态机节点封装正确。


## 三、串口双向通信联调（A5）

NUC与电控组ESP32板进行串口双向通信测试：

**NUC → ESP32（CTRL帧）**

发送 `CTRL,0.00,0.00,1,0,0`（开锁指令）

电控板日志显示收到指令并执行开锁动作，回应“Unlock pulse done”。

**ESP32 → NUC（POS帧，10Hz）**

NUC通过`status`命令查询到最新POS数据：
- 左编码器：0
- 右编码器：0
- 锁状态：解锁（0）
- 温度：25.5 ℃
- 湿度：60.0 %
- 电压：12.000 V
- 最近POS帧龄：0.089 s
- 通信健康：是

NUC发送控制指令，ESP32能正确接收并执行；ESP32按10Hz频率向NUC上报数据，NUC能正确解析。


## 测试结论

- A3 RTK定位：pynmea2库解析NMEA协议验证通过，代码逻辑正确，待室外实测。
- A4 状态机节点：7状态流转调试正常。
- A5 串口双向通信：成功实现NUC与ESP32板之间的指令下发与数据上报，CTRL帧和POS帧通信正常。

下一步计划：将RTK天线放置室外进行实际定位测试。
