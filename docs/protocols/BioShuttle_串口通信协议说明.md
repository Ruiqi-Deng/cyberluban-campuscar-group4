# BioShuttle 生物样品接驳车串口通信协议说明

版本：Demo v1.0  
日期：2026-08-21

## 1. 系统通信结构

系统由微信小程序、腾讯云后端、NUC、ESP32、RTK、摄像头及小车底盘组成。

- 微信小程序通过 HTTP API 创建寄件任务、查询状态并提交取件码。
- 腾讯云后端保存任务、生成样品编码与取件码，并向 NUC 下发任务命令。
- NUC 通过串口读取 ESP32 温湿度、电池和锁状态，并通过串口发送开锁命令。
- NUC 通过独立串口读取 RTK 的 NMEA GGA 定位数据。
- 摄像头通过 USB Video Class 接口连接 NUC。
- 当前 Demo 中底盘运动与真实开锁执行可采用模拟模式，云端任务状态机、遥测上传和小程序业务流程可正常运行。

## 2. ESP32 串口基本参数

| 参数 | 配置 |
| --- | --- |
| 接口类型 | USB 转 UART（CH340，USB VID:PID 1a86:7523） |
| 波特率 | 115200 bit/s |
| 数据位 | 8 bit |
| 校验位 | None（无校验） |
| 停止位 | 1 bit |
| 流控制 | None（无硬件/软件流控） |
| 常用表示 | 115200, 8N1 |
| 字符编码 | ASCII 兼容文本；调试信息为 UTF-8 兼容文本 |
| 帧边界 | 一行一帧，以 `\n` 或 `\r\n` 结束 |
| NUC 稳定设备名 | `/dev/serial/by-id/usb-1a86_USB_Serial-if00-port0` |
| 当前内核设备名 | `/dev/ttyUSB0`（可能随插拔改变，不建议写死） |

工程程序通过 Linux `by-id` 路径访问设备，避免把业务代码固定到可能变化的 `/dev/ttyUSB0`、`/dev/ttyUSB1` 编号。

## 3. NUC 向 ESP32 发送的控制帧

### 3.1 帧格式

```text
CTRL,<left>,<right>,<lock>,<reserved>,<photo>\n
```

当前 ESP32 固件解析 `CTRL,` 后的 5 个十进制整数。现阶段电机字段、保留字段及拍照字段不在 ESP32 内执行，拍照由 NUC 调用摄像头完成。

| 字段 | 类型 | 当前用途 |
| --- | --- | --- |
| `CTRL` | 字符串 | 控制帧固定帧头 |
| `left` | int | 预留/底盘左侧控制字段，当前锁控固件未使用 |
| `right` | int | 预留/底盘右侧控制字段，当前锁控固件未使用 |
| `lock` | int | `1` 表示触发一次开锁脉冲 |
| `reserved` | int | 保留字段 |
| `photo` | int | 预留拍照标志；当前由 NUC 独立完成拍照 |

### 3.2 开锁命令

```text
CTRL,0,0,1,0,0
```

ESP32 识别后应输出：

```text
[CMD] CTRL lock=1 photo=0
[ACTION] Unlocking, relay LOW 800 ms...
[ACTION] Unlock pulse done
```

执行逻辑为 GPIO5 输出低电平 800 ms，驱动低电平有效的继电器，然后恢复高电平。当前电磁锁只支持电控开锁；关锁由人工合上箱门后机械复位。

## 4. ESP32 向 NUC 上传的状态帧

### 4.1 帧格式

```text
POS,<enc_left>,<enc_right>,<lock_state>,<temperature_x10>,<humidity_x10>,<battery_mV>
```

示例：

```text
POS,0,0,0,221,809,12000
```

解析结果：

| 字段 | 示例 | 含义 |
| --- | ---: | --- |
| `POS` | POS | 状态帧固定帧头 |
| `enc_left` | 0 | 左侧编码器计数，当前锁控固件为占位值 |
| `enc_right` | 0 | 右侧编码器计数，当前锁控固件为占位值 |
| `lock_state` | 0 | 锁舌反馈状态 |
| `temperature_x10` | 221 | 温度扩大10倍，对应 22.1 ℃ |
| `humidity_x10` | 809 | 湿度扩大10倍，对应 80.9 %RH |
| `battery_mV` | 12000 | 电压字段，单位 mV；当前固件固定为占位值 12000，并非 ADC 实测 |

状态帧发送周期约为 500 ms，温湿度传感器读取周期约为 2 s。

### 4.2 当前锁反馈实测差异

固件设计定义为：

- `0`：UNLOCKED，锁舌缩回；
- `1`：LOCKED，锁舌伸出。

2026-08-21 实测中，电磁锁弹开后状态由 `0` 变为 `1`，与上述文字定义相反。因此真实闭环启用前需要检查 GPIO21 锁舌反馈接线及有效电平，并根据最终硬件修改固件映射。该问题不影响温湿度帧解析，但会影响 NUC 对开锁/关锁完成条件的判断。

## 5. RTK 串口协议

| 参数 | 配置 |
| --- | --- |
| 波特率 | 115200 bit/s |
| 数据位 | 8 bit |
| 校验位 | None |
| 停止位 | 1 bit |
| 流控制 | None |
| 数据协议 | NMEA 0183 文本 |
| 使用语句 | `$GNGGA` 或 `$GPGGA` |
| NUC 稳定设备名 | `/dev/serial/by-id/usb-AirM2M_AirM2M_Compo_000000000001-if06` |
| 当前内核设备名 | `/dev/ttyACM3`（可能随插拔改变） |

GGA 中主要提取纬度、经度和定位质量字段。室内测试可能得到空坐标且定位质量为 `0`，表示串口和模块有输出，但当前没有有效卫星定位解。

## 7. Demo 模式说明

由于底盘控制器返修、电磁锁降压模块损坏，演示使用 `BIOSHUTTLE_DRY_RUN=1`：

- 小程序真实调用腾讯云 API；
- 云端真实生成样品编码和取件码；
- NUC 真实轮询云端任务并上传遥测；
- 任务状态与取件验证真实执行；
- 底盘运动和锁动作使用软件模拟；
- 模拟证据文件用于验证四个业务阶段，不能表述为真实硬件拍摄证据。

建议演示画面标注“系统联调 Demo（执行器模拟模式）”。

## 8. 电气安全与待整改项

当前 36 V 标称电池满电电压约为 42 V。降压模块是否适用不能只根据“36 V 转 12 V”判断，必须核对其允许输入电压范围和最大连续/峰值输出电流。

降压模块在电磁锁动作瞬间损坏，后续重新上电前需完成：

1. 更换允许输入电压高于电池最高电压并留有裕量的降压模块；
2. 测量电磁锁额定电压、稳态电流和启动电流；
3. 检查输入输出极性、短路及公共地连接；
4. 为直流电磁锁线圈配置方向正确、参数合适的续流保护；
5. 在限流电源和保险丝保护下分阶段测试；
6. 修正锁舌反馈电平后，才允许将 NUC 切换到真实执行模式。

继电器触点 COM/NO 与 ESP32 控制侧原则上电气隔离。若系统不需要由 ESP32 对 12 V 电源进行模拟量采样，则降压模块 `OUT-` 通常不必与 ESP32 GND 共地；是否共地应以继电器模块实际电路、传感器接口和完整原理图为准。电磁锁线圈应在靠近线圈的位置设置续流保护，防止继电器断开时的感应高压冲击触点和电源模块。

在以上问题解决前，禁止重新给损坏的降压模块及电磁锁回路通电。
